# Freo Stone Production

Production tracking for pavers: what has been made, what is curing, what has
been shotblasted, and what is ready to be keyed into MYOB as stock. Runs in a
browser on a shop PC or a phone, works with the network down, and keeps its data
in places you own — your browser, your GitHub repo, your SharePoint exports. No
subscription, no hosted database.

## Where the data lives

| What | Where |
| --- | --- |
| Everything you enter | IndexedDB in the browser (`freo-production`) |
| The shared copy of that state | `state/state.json` in [`Freo-Stone/Production-App-Data`](https://github.com/Freo-Stone/Production-App-Data), private |
| Stock on hand, open jobs | `exports/location.xlsx` and `exports/future.xlsx`, MYOB's reports mirrored into that same private repo |
| The app itself | [`Freo-Stone/Production-App`](https://github.com/Freo-Stone/Production-App), public — source and the built site, with no data in either |

The browser is authoritative for writes; GitHub is how the other devices find
out. A push that collides comes back as a 409 and is merged after a reread, so
no device silently overwrites another.

## Running it

```
pnpm install
pnpm run dev        # http://localhost:5173
pnpm run build      # dist/, servable from any static host including GitHub Pages
pnpm test           # unit + jsdom component tests
pnpm run e2e        # playwright: desktop, phone, firefox
```

Four checks sit outside the unit and browser suites, because they need a built or
served copy: `pnpm run check:build` (what the build points at; this one runs in CI),
`pnpm run check:worker` (the app does not reload itself, and an update is still
offered and still applies when tapped), and `pnpm run probe:typing` with
`pnpm run probe:keystrokes` (what a keystroke actually costs). They are how the
dialog lag was found and how it is kept fixed — see `TASKS.md`.

Pushing to `main` runs `.github/workflows/deploy.yml`: tests, then a build with
the right `VITE_BASE`, then `scripts/check-build.mjs` resolving everything the page
and the manifest point at — and failing if the build output holds anything that is
not the app — then publish `dist/` to Pages at
`https://freo-stone.github.io/Production-App/`. The PWA manifest and service
worker are generated by the build, so the installed app and the URL are the same
program.

## The shape of a day

1. Power Automate (or a manual download) drops the current MYOB exports into the
   repo. The app pulls them and merges: stock rows replace, open jobs replace.
2. Production is entered against the day — line, product, trays. The curing clock
   starts.
3. Anything cured (and blasted, if it needs blasting) becomes ready stock.
4. On Friday, ready stock is listed for MYOB, keyed in, and marked entered.
   Until the next export from MYOB arrives, that stock is treated as counted.
   The weekday and cut-off are a setting; Friday is the default.

`TASKS.md` is the build plan and says which of those steps exist today.
